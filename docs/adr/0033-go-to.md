# 0033. Go to, and search later

## Status

Accepted

## Context

Getting to a project, folder, tag, or view means finding it in the
sidebar. With many projects that is slow, and a project the sidebar hides,
for being Done, Dropped, or Deferred, takes toggling the Show buttons
first.

What the user wants to reach is a short name they half-remember and may
type part of. Views, folders, projects, and tags are few: hundreds at
most, and the sidebar loads them already. Tags have autocomplete that
matches a path typed as `som/may` (ADR 0005).

Finding tasks by their title or notes is a different problem: tasks are
many, and a note can hold pages. That is left for later; the choice of
how to do it is recorded below so go-to does not get in its way.

## Decision

### Go to

- One dialog, **Go to**, opened by `/` or Cmd-K (Ctrl-K off a Mac) in
  both keymaps (ADR 0031), and by a button in the header. Cmd-K works
  while typing in a field; `/` does not.
- **Targets:** the views (Inbox, Open, Agenda, Flagged, Untagged, Import,
  Settings), and every live folder, project, and tag, whatever the
  sidebar shows. A blank query lists the views.
- **Matching** is the tag autocomplete's rule, now `Marskal.PathSearch`,
  over each target's path: a folder's or project's folders and its own
  name, a tag's ancestors and its name, a view's name. The query is split
  on `/ : › > \`; each piece is a case-insensitive prefix of a word, in
  order, and the last piece lands in the target's own name. So
  `wo/web` finds `Work › Website`.
- **Ranking:** an exact name first; then what the sidebar shows before
  what it hides; then fewer skipped path segments; then views, projects,
  folders, and tags, in that order; then shallower; then sidebar order.
  Up to 20 results.
- A hidden target is dimmed, and a Done or Dropped one says so.
- Choosing a result opens it as the sidebar link does: a record's page
  with the inspector on it.
- The targets load when the dialog opens. Each key matches them in
  memory on the server, with no query, so the dialog keeps up with typing.
- The dialog is a combobox: focus stays in the field, Up and Down move
  the selection, Enter follows it, and Escape closes.

### Offline clients

Clients have every folder, project, and tag locally. When one adds go-to,
`sync/core` gets the same matcher, with shared fixture vectors from
Elixir (ADR 0018). No sync API change.

### Task search, later

When tasks are searched by title and notes, it uses **pg_trgm**: a GIN
`gin_trgm_ops` index serves substring matches and typo-tolerant word
similarity on titles, and needs no language config for Danish and
English text. Notes match by substring only, since a long note would
fuzzily match nearly anything. Full-text search (`tsvector`) stems whole
words for one language and does not find part of a word; pgvector needs
an embedding model and is weak on exact names. Either may be added beside
pg_trgm later, for long notes or for search by meaning. Its results would
appear in the go-to dialog, below the places.

## Consequences

- Tag autocomplete and go-to share one matcher, so a change to how a
  query reads changes both.
- Go-to reaches what the sidebar hides without the Show toggles.
- Opening the dialog loads the user's folders, projects, and tags once.
- Task search needs its own ADR detail when it is built: the trigram
  similarity threshold, ranking, and how offline clients match it.
